# Agent Instructions

Rules for any AI agent working in this repository. These apply to all
languages present in the codebase (Dart, Kotlin, Swift/Objective-C, Gradle,
etc.) unless a rule is explicitly Dart-specific.

## Code style

- **Explicit variable types.** Do not use `var`, inferred `final` without a
  type, or other type-inference shorthand for declarations. Always write out
  the concrete type (e.g. `final String url = ...;`, not
  `final url = ...;` or `var url = ...;`). Function/method return types and
  parameter types must always be explicit too.
- **Strict null safety.** Treat nullability as meaningful, not decorative.
  Do not add `?` to a type just to silence the analyzer, and do not use `!`
  (null-assertion) to bypass a null-safety error unless the surrounding logic
  already guarantees non-null and that guarantee is stated in a comment.
  Prefer narrowing/guarding over force-unwrapping.
- Do not weaken analysis by adding `// ignore:` comments, loosening lint
  rules, or downgrading `analysis_options.yaml` to make errors disappear.
  Fix the underlying issue instead.

## Scope discipline

- **Do not invent functionality, files, abstractions, dependencies, or
  refactors that were not explicitly requested.** If a task seems to need
  something beyond what was asked (a new helper, a new dependency, a broader
  refactor), stop and ask instead of adding it unprompted.
- No speculative error handling, fallbacks, or configuration for cases that
  were not described. No "while I'm here" cleanups outside the requested
  change.
- If a request is ambiguous, ask a clarifying question rather than guessing
  and building on the guess.

## Git / commits

- **Only commit when explicitly asked to.** Making changes to files is fine
  during normal work; do not run `git commit` (or `git push`) unless the
  user directly requests it in that turn.
- **Use Conventional Commits** for every commit message
  (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`, `test:`, `build:`, etc.),
  with a concise imperative summary line.
- **Never mention the AI/assistant/agent in commit messages** — no
  "Co-Authored-By" trailers referencing an AI, no "Generated by", no
  self-reference of any kind. Commit messages should read as if written by
  the human author.
